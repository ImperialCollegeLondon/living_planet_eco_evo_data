Microclimate sensor data analysis in R

This tutorial is designed for ecologists and environmental scientists with basic R skills. You will learn how to analyze microclimate data collected with an EasyLog USB datalogger, focusing on loading, cleaning, and exploring, environmental time series data.

By the end of this tutorial, you will be able to:

  • Load EasyLog sensor CSV files

  • Clean your dataset and check for data quality issues

  • Identify and flag potential outliers using different methods

  • Visualize microclimate trends over time

  • Perform basic statistical summaries

  • Export cleaned data for further analysis

At the end, an optional extension shows how to compare data from multiple sensors and add habitat classification data.

The skills and methods you learn here apply broadly to other environmental datasets.

Read sensor data¶

Sensor data often contain inconsistencies such as mixed date formats or data types, which can cause issues during analysis. The format of the output files from the EasyLog sensors is also odd, there is the serial number field that only uses the first row. However, the main data is always in the first five columns. We can use the code below to compile the data into a data frame.

# Load one TXT file, handling Windows file encoding
logger_data <- read.csv(logger_file, encoding = "latin1")

# EasyLog's first column name contains the sensor ID. R converts a hyphen to a dot,
# so convert that dot back to a hyphen.
sensor_id <- sub(".", "-", names(logger_data)[1], fixed = TRUE)

# Keep the five measurement columns and give them consistent names
logger_data <- logger_data[, 1:5]
names(logger_data) <- c(
  "observation_id", "datetime", "temperature", "humidity", "dewpoint"
)

logger_data$sensor_id <- sensor_id

# Convert text fields to the types required for analysis
logger_data$datetime <- as.POSIXct(logger_data$datetime)
logger_data$temperature <- suppressWarnings(as.numeric(logger_data$temperature))
logger_data$humidity <- suppressWarnings(as.numeric(logger_data$humidity))
logger_data$dewpoint <- suppressWarnings(as.numeric(logger_data$dewpoint))

Identifying outliers¶

There are several ways to identify outliers. The table below summarizes three common methods with their pros and cons.

You already did the visual inspection; Z-score and Interquartile Range (IQR) method are described in more detail below.

Do you expect to get the same outliers with different methods?

Z-score method for outlier detection¶

The Z-score measures how far each value is from the mean, in units of standard deviations:

Z=value−meanstandard deviationZ = \frac{\text{value} - \text{mean}}{\text{standard deviation}}Z=standard deviationvalue−mean​
(1)

  • A Z-score of 0 = exactly the mean.

  • A Z-score of +2 = two standard deviations above the mean.

  • A Z-score of –3 = three standard deviations below the mean.

For normally distributed data, 99.7% of values lie within ±3 standard deviations. Values beyond this range are flagged as potential outliers.

logger_data_Z <- logger_data %>%
  mutate(
    temperature_Z = (
      (temperature - mean(temperature, na.rm = TRUE))
      / sd(temperature, na.rm = TRUE)
    ),
    temp_outlier_Z = abs(temperature_Z) > 3
  )

Interquartile Range (IQR) Method for Outlier Detection¶

The IQR method focuses on the spread of the middle 50% of the data. It calculates the difference between the 25th percentile (Q1Q_1Q1​) and the 75th percentile (Q3Q_3Q3​), called the interquartile range (IQR). Values falling below Q1−1.5×IQRQ_1 - 1.5 \times IQRQ1​−1.5×IQR or above Q3+1.5×IQRQ_3 + 1.5 \times IQRQ3​+1.5×IQR are considered potential outliers.

# Use the IQR method to flag temperature outliers
logger_data_IQR <- logger_data %>%
  mutate(
    temp_Q1 = quantile(temperature, 0.25, na.rm = TRUE),
    temp_Q3 = quantile(temperature, 0.75, na.rm = TRUE),
    temp_IQR = temp_Q3 - temp_Q1,
    temp_outlier_IQR = if_else(
      temperature < (temp_Q1 - 1.5 * temp_IQR) | temperature > (temp_Q3 + 1.5 * temp_IQR),
      TRUE, FALSE, missing = FALSE
    ),
  )

Clean and summarize the logger data¶

Choose one of the outlier methods and make a cleaned copy. Here we keep the IQR flags for inspection, but remove only IQR-flagged temperatures and missing values before calculating descriptive statistics.

clean_data <- logger_data_IQR %>%
  filter(!temp_outlier_IQR, !is.na(temperature))

clean_summary <- clean_data %>%
  summarize(
    observations = n(),
    start = min(datetime, na.rm = TRUE),
    end = max(datetime, na.rm = TRUE),
    mean_temperature = mean(temperature, na.rm = TRUE),
    minimum_temperature = min(temperature, na.rm = TRUE),
    maximum_temperature = max(temperature, na.rm = TRUE),
    mean_humidity = mean(humidity, na.rm = TRUE)
  )

print(clean_summary)

diurnal_data <- clean_data %>%

Flag outliers for every logger¶

Outlier calculations should be performed separately for each logger because each logger can have a different baseline, bias, and range.

all_data_IQR <- all_data %>%
  group_by(sensor_id) %>%
  mutate(
    temp_Q1 = quantile(temperature, 0.25, na.rm = TRUE),
    temp_Q3 = quantile(temperature, 0.75, na.rm = TRUE),
    temp_IQR = temp_Q3 - temp_Q1,
    temp_outlier_IQR = if_else(
      temperature < (temp_Q1 - 1.5 * temp_IQR)
        | temperature > (temp_Q3 + 1.5 * temp_IQR),
      TRUE, FALSE, missing = FALSE
    )
  ) %>%
  ungroup()

ggplot(
  all_data_IQR,
  aes(x = datetime, y = temperature, color = temp_outlier_IQR)
) +
  geom_point() +
  facet_wrap(~sensor_id) +
