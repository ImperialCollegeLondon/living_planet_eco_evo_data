Bulk processing acoustic data

Acoustic recorders generate a huge amount of data and processing it all can be a significant computing task. As an example, the recorders deployed in the field for this module in 2026 generated:

  • ~60,000 .WAV files across 13 sampled sites

  • ~320 GB of data

  • ~10,000 hours of recordings

Processing all of that data takes a lot of time. We could divide and conquer by giving you all a subset of files to process, but it’s really too big a task to coordinate. We could also just leave it running on a single computer for ages, but the best answer here is to use Imperial’s High Performance Computing (HPC) services.

This is an advanced topic, but the information below describes how we used the HPC to generate the species identification files from the audio files for this year.

Data collection and transfer¶

The recorders were retrieved and downloaded during November before they ran out of storage and power and the files were all transferred onto the file storage used for the HPC. The data are arranged as site-by-site folders of WAV files.

Computing setup¶

The HPC uses the conda package management tool, so first we need to use conda to define a virtual environment containing all of the code needed. The file below shows the commands used to do this.

Virtual environment setup
HPC_setup.sh
#! /bin/bash
# This script sets up a new R environment for processing the acoustics data on the HPC.

# We will use conda to create a new environment with the required packages. If a user
# has not installed conda, they can do so by running the following commands:
# module load miniforge/3
# miniforge-setup

# Once conda is installed, we can activate the conda commands and then create a new
# environment with the required R and python base packages:
# -  birdnet_analyzer requires python 3.11 - 3.13
eval "$(~/miniforge3/bin/conda shell.bash hook)"
conda create -n acoustics python=3.13 r-base=4.6.1 -c conda-forge

# Install R packages - soundecology does not seem to be in a channel so use CRAN
# This is tedious on a Linux system with the default CRAN repos that only serve source
# installs for Linux, so use the PPM repos to get binary installs.
conda activate acoustics
Rscript -e "install.packages('soundecology', repo='https://packagemanager.posit.co/cran/latest/bin/linux/centos8-x86_64/4.6')"

# Install python tools:
conda config --append channels conda-pypi
conda install -n acoustics birdnet-analyzer birdnet

Running tasks on the HPC¶

We need to run two bulk processing tasks:

  • calculating acoustic indices for all of the files, and

  • identifying bird calls in all of the files using Birdnet.

Running each of these tasks on the HPC requires two files:

  • A job submission script, written as a bash shell script, that tells the HPC what resources are needed to run the job and then sets the job running.

  • The actual job script, which contains all of the code needed to complete the tasks.

Because there are a very large number of files and the processing is identical for each site file, we can run these tasks as array jobs. By doing this, we can run the folders in parallel: the HPC will submit the same task multiple times and we can use a subjob index number to select a different site folders for each run.

Processing acoustic indices¶

The processing for the acoustic indices is basically identical to the example code used in the practical with the Monkswood and Parsonage Down files. We use the soundecology::multiple_sounds function and each subjob runs it on a single site directory.

Acoustic index job submission script
process_acoustic_indices.pbs.sh
#!/bin/bash

# Calculate acoustic indices using an array job to run by site. The upper limit on the
# number of subjobs set in the -J directive needs to match the number of site
# directories in the root data directory used in the called R script. Because
# `soundecology::multiple_sounds` supports parallelisation, this requests the maximum 16
# CPUs for the small24 queue.  Note that this uses R 1-based indexing to iterate over
# sites.

#PBS -lselect=1:ncpus=16:mem=128gb
#PBS -lwalltime=24:00:00
#PBS -J 1-13
#PBS -j oe
#PBS -o /rds/general/users/dorme/acoustics_2026/outputs/acoustic_indices_^array_index^.out

# Activate the conda environment containing the configured R environment
eval "$(~/miniforge3/bin/conda shell.bash hook)"
conda activate acoustics

# Echo the R version and start time
R --version
echo -e "In PBS.SH and running"
date

# Run the acoustic indices R script
Rscript --vanilla /rds/general/users/dorme/acoustics_2026/process_acoustic_indices.R

# Echo the end time and deactivate the conda acoustics environment
date
conda deactivate
Acoustic index job script
process_acoustic_indices.R
#' R script to batch process the calculation of acoustic indices from recordings for the
#' EcoEvoDataScience module. The directory structure needs to be structured as:
#'
#'        ── root
#'        │   ├── sites
#'        │   │   ├── site_name
#'        │   │   │   ├── Data
#'        │   │   │   │   ├── 20240802_054502.wav
#'        │   │   │   │   ├── 20240802_055002.wav
#'        │   ...
#'        ── outputs # created as needed
#'        ── script_files etc
#'
#' Each `site_name` directory is basically the contents of the data downloaded from the
#' song meters. The script is then expecting to be run in an array job and will use the
#' array index to pick up one of the site folders and process all the files in the
#' folder.

library(soundecology)

# Path handling
root_directory <- "/rds/general/users/dorme/acoustics_2026"
output_directory <- file.path(root_directory, "outputs")
if (!dir.exists(output_directory)) {
  dir.create(output_directory)
}

# Get the target site for this subjob
array_job <- as.integer(Sys.getenv("PBS_ARRAY_INDEX"))
sites <- sort(dir(file.path(root_directory, "sites")))
subjob_site <- sites[array_job]

# Get the path to the WAV file directory for this site
sites_directory <- file.path(root_directory, "sites", subjob_site, "Data")

# Run parallel processed calculation of ACI, NDSI and BI acoustic indices
multiple_sounds(
  directory = sites_directory,
  resultfile = file.path(
    root_directory,
    "outputs",
    paste0(subjob_site, "_ACI.csv")
  ),
  soundindex = "acoustic_complexity",
  min_freq = 1000,
  max_freq = 11000,
  no_cores = "max"
)

multiple_sounds(
  directory = sites_directory,
  resultfile = file.path(
    root_directory,
    "outputs",
    paste0(subjob_site, "_NDSI.csv")
  ),
  soundindex = "ndsi",
  no_cores = "max"
)

multiple_sounds(
  directory = sites_directory,
  resultfile = file.path(
    root_directory,
    "outputs",
    paste0(subjob_site, "_BI.csv")
  ),
  soundindex = "bioacoustic_index",
  no_cores = "max",
  min_freq = 1000,
  max_freq = 11000
)

Running Birdnet identification¶

We swap tools for this task. The birdnetR package is very good, but it is mostly a wrapper around the Python birdnet package and does not currently attempt to support all of the Python analytical tools available. The job script here uses Python and the birdnet_analyzer package to run the analyze function. This is functionally very similar to the multiple_sounds function we used above - it runs the process on all the files within a directory.

The job files for these two tasks are actually structurally very similar, just in different languages. The only extra complexity is that the birdnet task writes an output for each .WAV file, which the job script compiles into a single site file.

process_birdnet.pbs.sh

#PBS -lselect=1:ncpus=16:mem=128gb

Birdnet job script
process_birdnet.py
"""This script uses the Python birdnet_analyzer function to quickly process a site folder
of WAV files. This is more efficient than the single file processing in the birdnetR
package in R. The directory structure needs to be structured as:

       ── root
       │   ├── sites
       │   │   ├── site_name
       │   │   │   ├── Data
       │   │   │   │   ├── 20240802_054502.wav
       │   │   │   │   ├── 20240802_055002.wav
       │   ...
       ── outputs # created as needed
       ── script_files etc

Each `site_name` directory is basically the contents of the data downloaded from the
song meters. The script is then expecting to be run in an array job and will use the
array index to pick up one of the site folders and process all the files in the
folder.
"""

import os
import tempfile
from pathlib import Path

import pandas as pd
from birdnet_analyzer import analyze

ROOT_DIRECTORY = Path("/rds/general/users/dorme/acoustics_2026")


def analyse_directory():
    """Run birdnet_analyzer.analyze on an array subjob directory.

    This function runs analyze on a site directory selected by the PBS_ARRAY_INDEX value
    and then compiles the file by file identifications into a single site CSV file. It
    is structured as a function rather than a script to be compatible with the spawn
    process for using multiple threads.
    """
    # Path handling
    output_directory = ROOT_DIRECTORY / "outputs"
    output_directory.mkdir(exist_ok=True)

    # Get the path to the WAV file directory for this site
    array_index = int(os.getenv("PBS_ARRAY_INDEX"))
    sites = sorted((ROOT_DIRECTORY / "sites").glob("[!.]*"))
    site_directory = sites[array_index]

    # Write outputs to a temporary directory
    with tempfile.TemporaryDirectory() as tmp:
        # Run the analysis. This is equivalent to using the command line:
        #
        # python -m birdnet_analyzer.analyze \
        #     site_directory \
        #     --output output_directory --batch_size 32 --min_conf 0.1
        #
        # It is being run from within a python script mostly so that pandas can then be used
        # to compile the file by file outputs into a single site output file.

        analyze(
            audio_input=str(site_directory),
            output=tmp,
            batch_size=32,
            min_conf=0.1,
        )

        # Compile the per-WAV outputs into a single dataframe
        outputs = list(Path(tmp).glob("*.BirdNET.selection.table.txt"))
        data_frames = [pd.read_csv(f, delimiter=r"\t") for f in outputs]
        site_data = pd.concat(data_frames, ignore_index=True)

    # Process the columns to reduce to key data and use cleaner names
    site_data["file"] = [Path(x).name for x in site_data["Begin Path"]]
    site_data["start_time"] = pd.to_datetime(
        site_data["file"], format="%Y%m%d_%H%M%S.wav"
    ) + pd.to_timedelta(site_data["File Offset (s)"], "s")
    site_data["length"] = site_data["End Time (s)"] - site_data["Begin Time (s)"]
    site_data["site"] = site_directory.name

    # Reduce the data frame to only the required fields
    site_data = site_data[
        [
            "site",
            "file",
            "Common Name",
            "Species Code",
            "Confidence",
            "start_time",
            "length",
            "File Offset (s)",
        ]
    ]

    # Rename fields to remove spaces
    site_data.rename(
        columns={
            "Common Name": "common_name",
            "Species Code": "species_code",
            "Confidence": "confidence",
            "File Offset (s)": "file_offset",
        },
        inplace=True,
    )

    # Export compiled data to a site file
    site_data.to_csv(output_directory / f"{site_directory.name}_birdnet.csv")


if __name__ == "__main__":
    """Python syntax to define what happens when the script is run."""
    analyse_directory()
